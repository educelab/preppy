# Specification: `<dri-viewer>` web component

**Track ID:** viewer-widget_20260706
**Type:** Feature
**Created:** 2026-07-06
**Status:** Draft (revised 2026-07-07 after toolchain spike + deliverables grill)

## Summary
Build a minimal, embeddable three.js web component that loads one scene (a single
object's **variants**) and switches variants **without resetting the camera**,
with on-surface measurement and good default lighting.

## Context
Replaces DPO Voyager for this use case (ADR-0001). The widget's whole reason to
exist is camera-preserving variant switching, which Voyager can't do. It consumes
the per-object manifest produced by the delivery pipeline (ADR-0002 amended):
each variant is **one self-contained glb** (meshopt geometry + embedded KTX2). It
lives in the `dri-voyager` repo.

## User Story
As a scholar comparing an object's variants, I want to toggle RGB/IR/spectral in
place without losing my view or camera position, and measure features on the
surface, so I can study the object fluidly in an embedded widget.

## Acceptance Criteria
- [ ] `<dri-viewer manifest="…json" variant="<id>">` loads a scene: the default
      variant's glb, orbit/zoom/pan working; emits a `variant-change` event.
- [ ] **Variant switch preserves the camera**: switching shows the target
      variant's glb (geometry + embedded KTX2) with orbit controls untouched. (No
      shared-geometry `material.map` special-case — each variant is its own glb.)
- [ ] Several 8K KTX2 variants coexist without OOM on a mid-range phone.
- [ ] Two-point measurement returns distance in **cm** (manifest units) — the
      glTF node transform is applied to the mesh so raycasts read real scale.
- [ ] Default lighting reads the surface well; a raking-light control exists
      (default-only acceptable initially).
- [ ] Embeds with one `<script>` + one element, no runtime CDN.

## Dependencies
Depends on **toolchain-spike_20260706** (GO; validated stack, camera-preserving
swap, normals-in-viewer, `KHR_texture_transform`/node-transform handling). Soft
dependency on **delivery-pipeline_20260706** for real assets; can develop against
a hand-authored manifest + spike glbs until the pipeline lands.

## Out of Scope
Archive/object navigation (host page's job), annotations, tours, AR, and any
DPO Voyager feature we chose to drop.

## Technical Notes
three.js + GLTFLoader + MeshoptDecoder + KTX2Loader (+ Basis transcoder) +
OrbitControls, in TypeScript, bundled self-contained (Vite/esbuild) with the
transcoder wasm — **no runtime CDN** (the spike page's CDN import-map was
throwaway). Each variant loads via its own glb, so `KHR_texture_transform` is
handled by GLTFLoader (no manual reapplication) and normals are computed in-viewer
(`computeVertexNormals()`) since source geometry has none. Select variants by
stable `id`; keep the node transform on the mesh for cm measurement. See
Workstream B of `docs/implementation-plan.md`.
