# Specification: Harden & migrate

**Status:** Draft (revised 2026-07-07 after toolchain spike + deliverables grill)

## Summary
Enforce the tuning parameters (already chosen in the spike), harden the pipeline +
viewer for production, then migrate the existing Voyager back-catalog to the new
viewer as single-variant manifests.

## Context
Once the pipeline and viewer work on the new multi-variant data, the remaining
work is production hardening (Phase 4) and back-catalog migration (Phase 5) from
`docs/implementation-plan.md`. "New track first, migrate later" was the agreed
migration strategy (ADR-0001). Several tuning params are already settled by the
spike (see `spike/FINDINGS.md`): `-si 0.2` decimation, ETC1S default, units cm.

## Success Criteria
- [ ] Decimation budget (spike: `-si 0.2`) enforced as a Hausdorff gate in the
      pipeline (fail/warn on over-budget).
- [ ] KTX2 mode **confirmed** (spike: ETC1S default, per-variant UASTC option)
      and recorded as the default `--ktx2-mode`.
- [ ] Viewer memory policy validated on a mid-range phone across many variants.
- [ ] Cache-busting **retention policy** (keep-last-N) + host `Cache-Control`
      example (`.htaccess` once the target host is known: revalidate the manifest,
      long-cache hashed assets).
- [ ] Basic accessibility pass on the widget.
- [ ] **Generalization hardening (from viewer-widget MR !8 review):** the pipeline
      + viewer no longer assume the one test object's shape before the migration
      feeds them arbitrary legacy objects —
      (a) `bake_normals` handles source OBJs that already carry vertex normals and
      negative face indices (not just the normalless MVS OBJs);
      (b) the viewer's +Z surface-orientation assumption (raking-light basis +
      default framing) is either removed or documented as a delivery precondition;
      (c) the image-adjust shader warns instead of silently no-op'ing on a
      non-PBR material, and the caching/preload memory default is a deliberate,
      documented choice for many-variant objects.
- [ ] Docs updated: README, install of `ktx`(≥v5)/`gltfpack`/`gltf-transform`, CI
      reworked for the new toolchain (including the viewer typecheck/unit/e2e
      suites, deferred out of viewer-widget).
- [ ] Existing back-catalog objects re-emitted as single-variant manifests and
      served by the new widget; old Voyager path can be retired.

## Risk Assessment
- Legacy objects may use formats/quirks the new pipeline hasn't seen — migrate in
  batches, spot-check each.
- CI rework could break the smoke test; keep `voyager-preppy -h` green throughout.
- Retiring the Voyager site prematurely could break existing embeds — retire only
  after the migrated catalog is verified live.
